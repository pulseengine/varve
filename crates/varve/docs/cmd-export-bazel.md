# varve export-bazel [--layer <l>] --out <dir>

Compiles rules_wasm_component checksum registries from a verified layer — every hash Bazel enforces becomes a transcription from the signed manifest instead of TOFU.

`--layer` defaults to the resolved project pin, so the export tracks the pin. Every export writes a `.varve-export.json` stamp binding it to the producing layer; `varve verify --export <dir>` fails if the pin later moves and the export goes stale (REQ-EXPORT-SYNC-001).

In a MIXED project (`[toolchain.override.<tool>]`, REQ-OVERRIDE-001) the overridden tool's registry is written from the OVERRIDE layer's signed entry, so Bazel fetches the tool `varve run` dispatches. An override layer that records no source provenance for the tool gets no registry file for it — never the pinned layer's — and stderr says so, as for any tool without provenance. A re-export removes every `<tool>.json` the previous export here recorded that this one does not write — an override added, removed or swapped, or a pin moved to a layer without provenance for a tool — so the new stamp never seals a registry for a tool this project does not run. A `*.json` no earlier export recorded, or one edited since it was written, is refused rather than deleted or sealed. Every refusal, including "nothing exported", is decided before the directory is changed. Two composition layers disagreeing about an overridden tool refuse nothing: the override replaces it. The stamp records the mix.
